# 独立验证操作指南（中文）

> 本文件写给**不熟悉英文 README 的验证者**。跟着做即可，每步都给出确切命令与"看到什么算成功"。
> 配套英文材料：`README.md`（总说明）、各 `scripts/step*/README.md`（分步说明）。
> 本指南不重复它们的内容，只讲**怎么一步步动手**。

---

## 第 0 步：先搞清楚"能验证到什么程度"

这一步最重要。**不是所有结论都能从零重跑**，因为患者的原始影像与临床评分受伦理限制没有随包发布。

| 分析环节 | 能否从零重跑 | 原因 |
|---|---|---|
| Step 1 断连估计（LQT） | ❌ 不能 | 需要 124 例病灶掩码（患者数据，未共享） |
| Step 2 行为 PLS | ❌ 不能 | 需要个体 FSS-9 评分（患者数据，未共享） |
| Step 3 AHBA 表达重建 | ✅ 可以 | 公开数据，`abagen` 自动下载 |
| Step 4 基因排序 / 细胞富集 | ⚠️ 部分 | 需要 Step 3 的表达矩阵 |
| Step 5 GSEA | ✅ 可以 | 从 `w1` 排序 + 公开 GMT 即可 |
| Step 6 受体图谱 | ✅ 可以 | 从 LV1 loading + 公开图谱即可 |
| Step 7 特异性检验 | ⚠️ 部分 | 依赖上游产物 |
| **核对手稿里的每一个数字** | ✅ **可以** | **本指南的主线** |

**所以本指南分三档**，你按需要往下走：

- **档 0（约 1 分钟）**：`python repro_smoke_test.py` 快速健康检查（16 条）；`python check_pkg_hygiene.py` 打包卫生检查
- **档 1（约 10 分钟）**：一键核对稿件里的 **96 个数字**——这是绝大多数验证者要做的事 → 第 2–3 步
- **档 2（约 1 小时）**：亲手重算两个核心量，确认脚本不是"自说自话" → 第 4 步
- **档 3（数小时以上）**：完整重跑，需要第三方数据与网络 → 第 6 步（只给思路）

## 第 1 步：准备环境

**你要装的东西**：Python 3.10 以上（建议 3.11–3.13）。

**检查是否已装**：打开命令行（Windows 的 PowerShell 或 CMD），输入：

```
python --version
```

看到 `Python 3.x.x` 就通过了。若提示找不到命令，去 python.org 下载安装，安装时**务必勾选 "Add Python to PATH"**。

**安装本仓库需要的依赖**（在仓库根目录下执行）：

```
python -m pip install -r requirements.txt
```

这一步会装 pandas、numpy、scipy 等。**档 1 只需要这三个**；`requirements.txt` 里其余的是给档 3 完整重跑用的，装不上不影响档 1。

> 看到一堆 `Successfully installed ...` 就是成功了。若某个包报错，可以先跳过——档 1 用不到。

## 第 3 步（档 1）：跑一键核对

在仓库根目录执行：

```
python verify_manuscript_claims.py
```

**它会做一件事**：把稿件 Results 里的每一条数值声称，用 `derived_data/` 里的数据**重新算一遍**，逐条比对。

> ⚠️ 注意：这个脚本只读仓库内的 CSV，**不联网、不读作者本机任何路径**。所以它给出的"一致"是真·独立核对，不是作者预先写好的结论。

**你会看到这样的输出**：

```
===================================================================================
稿件结论逐条核对（重算值仅来自 derived_data/）
===================================================================================
章节     稿件声称                                       重算值      期望值  结论
-----------------------------------------------------------------------------------
3.2    corr(Lx, Ly) = +0.317                        0.317      0.317  PASS
3.2    载荷为正的区域 = 80/100                          80         80  PASS
...
3.6    α4β2 与 GABA-A r = −0.248（由 100 区重算，临界值）  -0.248     -0.248  PASS
-----------------------------------------------------------------------------------
合计 96 条：PASS 96 ｜ FAIL 0
```

**看到 `FAIL 0` 就算通过**。若有 FAIL，回到第 5 步查原因。

**建议你把输出存下来留档**：

```
python verify_manuscript_claims.py > 核对结果.txt
```

## 第 4 步（档 2）：亲手重算一个核心量

档 1 是"读现成的表核对"。如果你想确认**这些表本身也是算出来的、不是编的**，做下面两个练习。

### 练习 A：从 100 个区的原始数值重算受体图谱之间的相关

稿件 §3.6 说三张显著图谱彼此相关（α4β2 与 μ-阿片 r = +0.515 等）。这些 r 是 100 个皮层区上的皮尔逊相关。你可以自己算一遍：

```python
import pandas as pd, numpy as np

# 读 21 张图谱 × 100 区的原始数值（前 5 列是说明，其后 100 列是区值）
pv = pd.read_csv('derived_data/receptor_parcel_values_21x100.csv')
X = pv.iloc[:, 5:].values.astype(float)

# 算 21×21 的相关矩阵
C = np.corrcoef(X)
t = list(pv['target'])
i, j = t.index('a4b2-nACh'), t.index('GABA-A')
print('α4β2 与 GABA-A 的 r =', C[i, j])      # 应为 -0.2484959...
```

**预期**：输出 `-0.2484959...`，四舍五入到三位是 **−0.248**，与稿件一致。

> **⚠️ 这里藏着一个坑，值得单独记住。**
> 仓库里另有一个 `receptor_21x21_correlation.csv`，里面把每个值**已经预先四舍五入到 4 位**了，
> 那对值是 **−0.2485**。如果你偷懒、直接拿这个表再四舍五入到 3 位，会得到 **−0.249**，
> 与稿件对不上——**这是二次舍入造成的假警报，不是稿件的错**。
> 经验：**核对临界值时，一定要回到全精度数据重算**，不要在已经舍入过的中间表上再舍一次。
> （`verify_manuscript_claims.py` 就是按全精度算的，所以它能给出正确的 PASS。）

### 练习 B：统计"20 个种子都显著"这类稳健性说法

稿件 §3.4 说"20 个独立种子重跑，仅少突胶质前体细胞 0/20，其余均 20/20 达 p < 0.05"。自己数一遍：

```python
import pandas as pd
ms = pd.read_csv('derived_data/multiseed_celltype_Dataset5_p.csv', index_col=0)
print(ms.shape)                       # 应为 (20, 7)：20 个种子 × 7 类细胞
for col in ms.columns:
    print(col, (ms[col] < 0.05).sum(), '/ 20')
```

**预期**：`Micro`、`Oligodendrocytes`、`Astro`、`Endo`、`Excitatory_Neurons`、`Inhibitory_Neurons` 都是 `20 / 20`，只有 `OPC` 是 `0 / 20`。

## 第 5 步：拿到 FAIL 怎么办

先别急着下"稿件有错"的结论。按顺序排查：

1. **是不是精度/舍入问题？** 最常见的假 FAIL。做法：找到原始全精度值，只看四舍五入后是否与稿件一致。参考练习 A 的坑。
2. **是不是我读错了列/行？** 检查 CSV 的列名与索引（有些表首列是行索引，有些是普通列；有些行索引是图谱文件名，有些是靶点简称）。
3. **是不是数据版本不一致？** 本仓库数据对应 2026-09-17 版本，文件名里的 `_20260915` 是数据版本标记。
4. **确认为真实差异**：记录（章节、稿件值、重算值、全精度值、你用的输入文件），这就是一条有价值的验证发现——**这正是独立验证的意义**。

只给思路，不展开——因为这需要你自备第三方数据。

## 第 7 步：核对不了的部分（请明确知道）

以下结论**无法**通过本仓库独立验证。分两类原因：**缺患者级数据**，或**缺未随包的第三方资源**。

**（一）缺患者级数据（病灶掩模 / 临床量表）**

| 稿件位置 | 内容 | 为什么核对不了 |
|---|---|---|
| §3.1 / Methods 2.1 | 124 例样本特征、FSS-9 分布（中位 9、IQR 9–38.3；61.3% 处于量表下限）、病灶体积中位 2.6 mL | 个体临床评分与病灶掩模未共享 |
| §3.2 | LV1 解释 94.0% 交叉协方差；主检验置换 *p* = 0.023（*n* = 5,000） | 需要个体 FSS-9 重跑 PLS |
| §3.2 | 病灶体积与 FSS-9 的相关（ρ = +0.024, *p* = 0.791） | 需病灶体积 + FSS 条目 |
| §3.2 | 秩变换载荷与主分析载荷的空间相关（*r* = +0.981） | 需秩变换后的载荷向量 |
| §3.2 | 脑分数 vs 打乱 FSS-9 的 10,000 次相关置换（*p* < 0.001 / 0.001） | 需个体层面数据 |

> 📌 **native↔MNI 体积守恒已随包**：`derived_data/volume_conservation_qc_N124.csv` 给出全部 124 例的
> native / T1 / MNI152 三套掩码体积、比值（`MNI/native`）、MNI 空间质心与 PASS 标记。
> 稿件 Methods 2.3 现在只写「逐例复核体积守恒」，**该声称可由此文件独立核对**
> （比值中位 1.268、范围 0.890–1.635，全部落在预设 0.5–2.0 容差内）。

**（二）缺未随包的第三方资源（AHBA 表达矩阵 / GO-KEGG GMT）**

| 稿件位置 | 内容 | 为什么核对不了 |
|---|---|---|
| §3.4 | HPA 脑表达过滤后重跑（小胶质/少突 BH-*p* < 0.001；星形 0.091、内皮 0.214；OPC 0.993 → 0.818） | 需 AHBA 表达矩阵（可由 Step 3 脚本重建） |
| §3.5 | 通路表达图的 5 个 *r* 值（+0.366 ~ +0.408）；HPA 过滤后的 GO 125 / KEGG 28 | 需重跑通路表达图与 HPA 版 GSEA |
| §3.5 | 断连负荷对照 GSEA（GO 2 条、KEGG 0 条） | 需 burden 排序的 GSEA 结果 |
> **2026-09-19 随稿件瘦身删除的两项**：「疾病通路交集（96 基因 / Thermogenesis∩OXPHOS 103/133）」与「层间独立性的超几何检验」已从正文与补充材料中删除，故不再列入本表。

**（三）供体稳健性（§3.3）—— 本仓库已完整支持**

原先只有 `lodo_donor_robustness_report.txt`（6 个 *r* 值）。现已补入
`lodo_consistency_by_donor.csv`、`lodo_common90_r_by_donor.csv`，
所以 §3.3 仍在报告的两类数值（各供体 *r*、公共 90 区重算 *r*）**都可核**。

> 🗂️ **已随 2026-09-22 修订删除的一项**：top-300 基因列表的 Jaccard 重叠，
> 连同承载它的补充图 **Fig. S1**（基因排序 LODO 图）一并从稿件删除。
> 原数据文件 `lodo_top300_jaccard_by_donor.csv` 与同批 superseded 分析已于 2026-10-10
> 归档至本仓库之外（移动、未删除），本仓库内不再提供该文件。
> 核对脚本 `verify_manuscript_claims.py` 已不再检查 Jaccard，故**无需**核对这一项。

**这些不是"包做得不好"，而是患者数据与第三方资源不能随包发布的必然结果。** 稿件已在 `Data and code availability` 中说明数据边界；AHBA 相关部分可由 Step 3 脚本从公开数据重建。
